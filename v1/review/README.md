# Архитектурные проверки Elm

`review/` — отдельный Elm-проект конфигурации и правил, не часть приложения.
Зависимости зафиксированы в [elm.json](elm.json), npm CLI — в
[../package.json](../package.json) и lockfile. Компилятор остаётся локальным Elm
0.19.3; совместимость проверяется реальным запуском, не только диапазоном версий.

## Запуск

Из корня всего проекта:

```sh
npm --prefix v1 run review          # анализ приложения и его Elm-тестов
npm --prefix v1 run test:review     # тесты правил и состава конфигурации
npm --prefix v1 run check           # обе проверки включены в общую цепочку
```

Скрипты явно выбирают компилятор из `v1/node_modules/`, а не глобальный Elm.
`review` работает без `--fix` и с `--unsuppress`: существующие suppression-файлы
не скрывают нарушения. Ошибка правила, конфигурации или компиляции останавливает
`check`. Review-пакеты не добавлены в зависимости приложения.

## Включённые правила

Конфигурация — [src/ReviewConfig.elm](src/ReviewConfig.elm).

- `NoDebug.Log` и `NoDebug.TodoOrToString` из `jfmengels/elm-review-debug`:
  запрет `Debug.log`, `Debug.todo`, `Debug.toString`.
- `NoExposingEverything` из `jfmengels/elm-review-common`: явный список экспорта
  модуля вместо `exposing (..)`. Открытые конструкторы других типов разрешены.
- `Architecture.DomainBoundary`: точный модуль `Domain` импортирует только
  утверждённые чистые модули ядра и `Json.Decode`/`Json.Encode`. Также запрещены
  обращения к значениям и типам `Platform`, `Platform.Cmd`, `Platform.Sub`.
- `Architecture.PortsOnlyInMain`: port modules и объявления ports разрешены
  только в точном модуле `Main`, не в `Main.Child` или другом помощнике.
- `Architecture.KeepLevelOpaque`: в `Domain` нельзя экспортировать `Level(..)`
  или всё содержимое модуля и нельзя заменить `Level` прозрачным type alias.

Domain использует allowlist, а не blacklist известных эффектных библиотек:
новый помощник нельзя незаметно протащить вместе с транзитивной зависимостью от
UI. Чистые `Array`, `Basics`, `Bitwise`, `Char`, `Dict`, `List`, `Maybe`, `Result`,
`Set`, `String`, `Tuple` разрешены. Новый чистый импорт требует явного изменения
политики и её тестов, не локального подавления сообщения.

Типы и значения эффектов определяются по разрешённому имени модуля через
`ModuleNameLookupTable`. Проверяются неявные `Cmd`/`Sub`, alias и exposed-имена,
вложенные записи, кортежи, параметры типов, аргументы конструкторов и локальные
сигнатуры в `let`. Чистый локальный тип `Cmd` или чистый модуль с таким alias
не считаются эффектами. Комментарии и строки не анализируются как код.

## Тесты и пределы гарантий

В [tests/](tests/) — 49 положительных и отрицательных тестов. Они проверяют
допустимый код, нарушения и обходы; отдельный тест закрепляет шесть правил
в рабочем `ReviewConfig`. Для изменений правил обновляй тесты и запускай весь
`check`, не только проверку текущего приложения.

Проверки относятся к исходному Elm-коду приложения и его тестов. Они не
анализируют JS и не доказывают:

- корректность Web Locks, snapshot check и ответов browser bridge;
- отсутствие сетевой передачи или логирования в JS;
- смысл переходов сохранения/удаления и корректность JSON-декодеров;
- диапазон `Level` или отсутствие обходной фабрики с неверной реализацией.

Это структурные архитектурные ограничения, не формальное доказательство
поведения. Domain-тесты и Playwright остаются обязательными. Новые ports внутри
`Main` этим правилом не запрещены: их контракт требует отдельного review.
Имена `Domain` и `Main` — часть политики; при переносе или переименовании модулей
её нужно осознанно обновить вместе с конфигурацией и тестами.
