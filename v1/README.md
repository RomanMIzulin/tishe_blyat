# Тише · v1

«Тише» — сервис, то есть услуга для работы с психологическим напряжением в моменте. Elm-приложение на английском и русском языках — способ её оказания: оценка состояния, дневник, практики внимания и телесные практики, раздел Why с философскими и психоаналитическими основаниями. Спокойствие не обязательный результат, а низкая оценка напряжения не критерий успеха.

## Язык интерфейса

При первом открытии используется **английский**, независимо от языка браузера. Переключатель **English / Русский** находится в верхней панели и доступен с клавиатуры. Он переводит навигацию, поля и доступные названия, даты, практики с их ограничениями, теорию и сообщения хранилища. Название в английском интерфейсе — **Tishe**.

Выбор запоминается отдельно от дневника в `localStorage` под ключом `tishe.language.v1` (`en` или `ru`). Неизвестное или недоступное значение означает английский по умолчанию. Если браузер запрещает запись настройки, интерфейс сообщает об этом, а переключение работает до перезагрузки. Язык между уже открытыми вкладками автоматически не синхронизируется.

Смена языка не сбрасывает незаписанную форму, выбранную практику, таймер или фильтр дневника. Заметки не переводятся; ключ `tishe.entries.v1`, схема JSON и значения чувств в экспорте не меняются. Удаление дневника не удаляет настройку языка.

## Запуск

Нужен Node.js **22.12+** и npm. Из корня репозитория:

```sh
cd v1
npm ci
npm run dev
```

Открыть **http://localhost:5173**. Изменения Elm пересобираются через Vite с перезагрузкой страницы; JS и CSS поддерживают обычное обновление Vite. Черновик формы и незаписанная практика при перезагрузке не сохраняются.

В проект установлен **Elm 0.19.3** (`elm@0.19.3-0`), обновлён и `elm-test`. Версии зафиксированы в `elm.json` и `package-lock.json`. Глобальный компилятор не меняется; npm-скрипты используют локальный.

```sh
npx elm --version
npm run build
npm run preview -- --port 4173
```

Production-файлы находятся в `dist/`. Это статический сайт, backend не требуется. Для публикации использовать HTTPS. По умолчанию сборка рассчитана на корень домена; для подпапки задай `VITE_BASE_PATH` с начальным и конечным `/`:

```sh
VITE_BASE_PATH=/tishe_blyat/ npm run build
VITE_BASE_PATH=/tishe_blyat/ npm run preview -- --port 4173
```

Открыть **http://localhost:4173/tishe_blyat/**. `file://` не поддерживается.

### GitHub Pages

Workflow [`.github/workflows/pages.yml`](../.github/workflows/pages.yml) при push в `main` устанавливает зависимости по lockfile, запускает `check` и Playwright + axe на desktop и mobile под путём репозитория, затем публикует только `v1/dist/`. Исходники, зависимости и отчёты не входят в сайт. Неудачная проверка блокирует публикацию. Workflow также можно запустить вручную во вкладке Actions.

В репозитории один раз выбери **Settings → Pages → Build and deployment → Source: GitHub Actions**. Ожидаемый адрес: **https://romanmizulin.github.io/tishe_blyat/**. HTTPS предоставляет GitHub Pages; собственного backend нет. Права на публикацию (`pages: write`, `id-token: write`) есть только у deploy-job.

Для локальной проверки такого же адресного пути:

```sh
VITE_BASE_PATH=/tishe_blyat/ npm run test:e2e
```

## Что работает

- **Сейчас:** субъективный уровень напряжения 0–10, несколько чувств, необязательная заметка до 2000 символов. Любое значение остаётся личным наблюдением: высокий уровень не запускает предупреждения или особый сценарий.
- **Дневник:** реальные записи с локальными датами, фильтры за последние 7/30 суток или всё время; на главной — последние семь наблюдений, без выдуманных данных, серий и «оценки успеха».
- **Практики:** две группы — «Внимание и выбор» и «Тело и движение». В первой — возвращение в настоящее, различение доступного выбора и обстоятельств, внимание к конфликтующим желаниям. Во второй — девять практик: ходьба на носках с опорой, вытяжение макушкой вверх, прогулка с вниманием, прикосновения к телу, постукивание подушечками пальцев, самомассаж мышц, массаж головы и лица, внимание к движению дыхания и тёплые ладони перед глазами без давления. У каждой — три шага и собственные ограничения, видимые до запуска. Таймер на минуту — необязательный ориентир, не дозировка; все шаги доступны без него. Смена практики или группы сбрасывает таймер. Часы учитывают задержки фоновой вкладки, а паузы сохраняют миллисекунды. Основания и исключённые варианты — в [редакторской заметке](../docs/body-practices.md).
- **Почему:** стоицизм, феноменология и психоанализ, первичные источники, границы авторской адаптации и заметка о свободном темпе практики.

Дневник можно скачать в JSON или полностью удалить после подтверждения. Импорта, синхронизации между устройствами, аккаунтов и серверного хранения в v1 нет.

## Данные и безопасность

Записи хранятся **без шифрования** в `localStorage` текущего origin под ключом `tishe.entries.v1`. Экспортированный JSON тоже не зашифрован. На общем устройстве дневник не является приватным от других пользователей браузера. Очистка браузера, приватный режим и смена адреса/порта могут сделать записи недоступными.

Пути внутри одного origin не изолируют `localStorage`: другие сайты на `romanmizulin.github.io`, включая другие репозитории GitHub Pages этого аккаунта, могут иметь доступ к тем же ключам. Для изоляции от них нужен отдельный домен. GitHub обслуживает файлы сайта и получает обычные HTTP-запросы загрузки, но содержимое дневника в них не передаётся.

Приложение не отправляет записи на сервер, не содержит аналитики и не загружает внешние шрифты. Шрифты Golos Text и Lora поставляются локально. Ссылка на первоисточник открывает внешний сайт только по нажатию.

Запись использует **Web Locks** и проверку исходного снимка хранилища. Требуется современный браузер и безопасный контекст: HTTPS либо localhost. На обычном HTTP вне localhost при отсутствии Web Locks приложение оставляет новую запись в памяти и показывает ошибку вместо небезопасной записи.

Если другая вкладка изменила дневник, устаревшая вкладка не перезапишет его: появится предупреждение. Новый момент останется в памяти этой вкладки — скачайте JSON **до перезагрузки**. Автоматического объединения конфликтующих версий нет. Ошибка удаления сохраняет записи на экране и позволяет повторить операцию. Удаление очищает весь дневник этого origin, включая записи другой вкладки; это осознанная глобальная операция.

Некорректный JSON или неизвестная схема не сбрасываются молча: сохранение блокируется, исходное значение остаётся в браузере до явного удаления. Для ручного восстановления скопируйте значение ключа через инструменты разработчика. При блокировке/переполнении хранилища новый момент доступен только в памяти; UI предлагает скачать копию.

## Проверки

```sh
npm run check
npx playwright install chromium
npm run test:e2e
```

`check` проверяет форматирование приложения и review-проекта, запускает **39 Elm-тестов приложения** и **49 тестов архитектурных правил**, выполняет **elm-review**, затем собирает оптимизированный Elm и production-сайт. Fuzz-проверки покрывают инварианты уровня и JSON. `test:e2e` запускает **38 проверок Chromium**: 19 сценариев на desktop и мобильном viewport. Они проверяют сохранение, экспорт, перезагрузку, удаление и его отказ, повреждённое/недоступное хранилище, конфликт вкладок, фильтры, таймер, каталог телесных практик и его ограничения, сброс при смене практики или группы, теорию и отсутствие внешних запросов при загрузке. Локализация проверяется на обоих языках: английский по умолчанию, сохранение выбора, неизвестная настройка, отказ её записи, клавиатурное переключение без потери формы и сохранение работающего таймера.

Axe проверяет основные экраны на обоих языках на автоматизируемые правила WCAG A/AA, включая контраст. Это не заменяет ручной аудит клавиатуры и screen reader. Скриншоты главной и основных разделов сохраняются в `test-results/`; мобильная проверка — эмуляция Chromium, не физический iPhone/Safari.

```sh
npm run format
npx prettier --write src/*.js src/*.css scripts/*.mjs e2e/*.js *.js *.json index.html README.md review/elm.json review/README.md
```

## Архитектурные ограничения

```sh
npm run review       # правила на приложении и его Elm-тестах, без автофиксов
npm run test:review  # тесты самих правил и состава конфигурации
```

Локальный `elm-review@2.13.5` работает с установленным Elm 0.19.3. Конфигурация и Elm-зависимости правил изолированы в `review/`, не входят в зависимости приложения. Включены запрет `Debug`, явный список экспорта модулей и три проектных правила: утверждённые чистые импорты и отсутствие `Program`/`Cmd`/`Sub` в `Domain`, ports только в `Main`, непрозрачный custom type `Level`. Alias и неявные импорты эффектов также проверяются.

`review` запускается с `--unsuppress`: suppression-файлы не скрывают нарушения. Эти проверки не доказывают правильность JS bridge, сохранность данных или смысл переходов состояний — поведенческие тесты остаются обязательными. Политика, allowlist и ограничения описаны в [review/README.md](review/README.md).

## Устройство и решения

- `src/I18n.elm` — конечный тип языка, декодирование настройки, выбор обязательной пары английского и русского текста, метаданные страницы. `src/Content.elm` — локализованные подписи чувств, уровней и практик; представление отделено от предметной модели.
- `src/Domain.elm` — чистая модель: непрозрачный `Level`, конечный набор чувств и практик, JSON-граница, состояния таймера. Нет IO и зависимостей от DOM.
- `src/Main.elm` — Elm Architecture: модель, события, переходы, подписки и экраны. Ошибки хранилища и операция удаления представлены отдельными типами; удаление завершается только после подтверждения JS.
- `src/Theory.elm` — теоретические оптики, тексты, источники и оговорки. Это не диагностический движок.
- `src/bridge.js` — минимальная граница IO: localStorage, Web Locks, скачивание JSON и применение языка/метаданных документа через ports. `src/styles.css` — адаптивная вёрстка, локальные шрифты, видимый фокус и учёт reduced motion.

Elm выбран по требованию проекта: состояния и переходы проверяет компилятор. localStorage выбран для автономного прототипа без передачи чувствительных заметок серверу, ценой отсутствия шифрования, восстановления и межустройственной синхронизации. Сохранение намеренно ручное: черновики не записываются незаметно. Философские подходы не объединяются в «доказанную терапию»: у каждого в UI собственная оптика и явно обозначенная граница применимости.

## Теория и границы

Источники: Эпиктет, «Руководство», § 1; Эдмунд Гуссерль, «Идеи к чистой феноменологии…», книга I, §§ 27–32; Зигмунд Фрейд, «Лекции по введению в психоанализ», лекция 23, и «Торможение, симптом и тревога» (1926). Тексты интерфейса — адаптация, не цитаты. Феноменологическое описание переживания здесь не равно строгой феноменологической редукции; конфликт и защита — возможные гипотезы, не установленные причины.

У приложения и этой комбинации упражнений **нет клинической проверки**. Первичные философские и психоаналитические источники не доказывают лечебную эффективность. Перед публичным позиционированием как продукта психического здоровья нужна профессиональная клиническая редактура.

Это инструмент повседневного самонаблюдения, не диагностика и не терапия. Высокая субъективная оценка напряжения не трактуется как кризис и не запускает спасательный сценарий. Любой вопрос можно пропустить, а неприятную практику — остановить.
